# ADR-0001: 初期版は Next.js で画面と API を一緒に配信する

## Status

Accepted

記録日：2026-11-24

## Context

collebox では、作品・シリーズ・所持状態の組み合わせを実際に操作しながら、検索画面と検索条件を繰り返し改善したい。個人開発で当面は無料運用を目指す。React + Vite と Go REST API を別々に配信する案も検討した。

## Decision

初期版は Next.js App Router と TypeScript を採用する。画面と API は一つのアプリとして配信する。検索条件の解釈、達成率、保存ルールは Next.js のリクエストや画面から独立したサーバーモジュールに置く。

## Consequences

- 検索フォームとサーバー側の条件を一つの TypeScript プロジェクトで変更できる。初期版の起動・配信先も一つで済む。
- 検索 API だけを独立して増強・配信する段階では、境界を HTTP 契約として定義し、切り出す作業が生じる。モバイルから同じ API を利用したくなった場合も見直す。[構成図と移行手順](../04_architecture.md)

## Alternatives

**React + Vite と Go REST API を別々に配信する案（検討済み）**。画面と API を独立して更新でき、Go で検索処理を実装する経験も得られる。初期から二つの実行環境を扱い、検索条件を変えるたびに TypeScript と Go の間の取り決めを更新する手間がある。今回は一人で分類・検索の使い心地を繰り返し改善することを優先した。Go は将来の切り出し先の候補とする。
