# ADR-0002: グッズ情報と本人認証に Supabase を使う

## Status

Accepted

記録日：2026-11-24

## Context

本人だけが使うコレクション帳でも、検索・更新する範囲を所有者に限定する必要がある。検索では作品、シリーズ、所持数を組み合わせ、コンプ率は同じ種類を重複して数えずに集計したい。

## Decision

構造化したグッズ情報は Supabase PostgreSQL に保存し、本人のログインとセッション管理は Supabase Auth に任せる。サーバーは検証済みのユーザー ID から所有者を特定する。

## Consequences

- 作品・シリーズ・所持状態の絞り込みと集計を SQL で記述できる。[データモデル](../03_data-model.md)
- DB と認証の運用を Supabase に任せられる。アプリ側では検索・保存・画像操作の各入口で所有者を照合する。
- 無料運用では DB 接続数やサービスの利用枠を考慮する。DB アクセスライブラリとマイグレーションツールは未定。

## Alternatives

**PostgreSQL を自分で運用し、認証を別途用意する案（設計条件に基づく比較）**。同じ SQL を使いながら、DB の配置と認証方式を個別に選べる。初期版から DB の更新・バックアップと認証の組み込みを個人で管理する負担が増えるため、採用方針では Supabase に両方をまとめた。
